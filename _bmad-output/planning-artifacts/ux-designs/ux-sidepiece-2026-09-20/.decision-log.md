## 2026-09-20 — Core experience priorities (Jarad)

Ranked moments that define success:

1. **"Finger on the clipboard" — exact visual reference.** Point at an exact
   element, style, tab group, etc. on a live web page and have the agent
   unambiguously know what "this right here" means. Terminal-based description

   agent says "okay" → user *trusts* it understood.

   pages currently means juggling a separate tickets tab with no visual cues,

Design implications (signals, not yet decisions):
- ADHD-friendly: minimize working-memory burden, no modal context switches,
  visual cues over text recall.
- Success metric: friction removed from feedback communication.
- "Colleague already has context" is table stakes via Hermes; the *visual*
  pointing is the differentiator.

### Findings that change the design

**The state count is wrong.** FR-3 calls itself the authoritative taxonomy of degraded
states and lists six, but FR-5's no-PM-declared and PM-declared-but-not-running, plus
FR-12's no-Board, each gate a whole pane and appear in none of the six. The real count is
**at least nine**, each owing separate wording and its own re-resolve control. This is the
single largest authoring obligation in the run.

**Two failure rules contradict.** §5: "Every pane fails independently and says why."
UJ-3: when the Bridge is unreachable "every pane says so with one shared message rather
than each failing in its own way." The PRD never reconciles them.
**[ASSUMPTION — resolved in EXPERIENCE.md]** the split is total-outage vs partial-outage:
one shared message when the Bridge itself is unreachable (nothing can be true), per-pane
messages when the Bridge answers and a single dependency behind it is down.

**The PRD dictates facts, not sentences — with five exceptions it quotes literally:**
"the PM has your turn", "warming up the PM", "this tab is resolvable",
"declared but unknown", and a "degraded-connection indicator". Voice and Tone inherits
those verbatim.

**FR-7 forbids the easy pre-token state.** The gateway's `thinking.delta` placeholder does
not count as a first token — "rendering that as the answer would be measuring an
animation." So the chat pane needs a visible pre-token state that is neither the answer
nor a bare spinner.

**The panel dies on *collapse*, not only on close.** The Cockpit document is fully torn
down whenever the panel is collapsed. Anything the annotation list holds in the panel is
gone at that moment — which decides where annotation state can live.

**A page click *can* open the Cockpit.** Chrome curries a user gesture across exactly one
`runtime.sendMessage` hop, so content-script button → service worker → `sidePanel.open()`
works, provided the chain is callbacks with zero awaits. Neither the PRD nor the addendum
records this; it is what lets an in-page annotation flow summon the panel.

**New platform surface since 2026-09-17:** `chrome.sidePanel.onOpened` / `onClosed`
(Chrome 141+, fleet runs 151–155) and `runtime.getContexts({contextTypes:['SIDE_PANEL']})`
— a save/restore hook the addendum did not know existed.

**~320px is a hard floor.** Chrome 149 pins a minimum side-panel width; the extension can
neither set, suggest, nor read it. FR-4's always-visible repo + full clone path + Board id,
the composer with FR-6's visible classification and flip control, FR-10's context preview,
FR-12's grouped Tickets and the annotation list all compete in one column at that width.
This is an IA constraint, not a styling one.

**The picker has two implementations with a real cost each.** `chrome.debugger`'s
`Overlay.setInspectMode` draws a browser-native outline no page can break, but pins a
"Sidepiece started debugging this browser" infobar to every tab on every activation. The
hand-built alternative is a closed shadow root + CSS-layer reset + `position:fixed` +
`z-index:2147483647` — the technique DevTools' own UI uses — which some pages will still
break via ancestor `transform`/`filter`/`contain` or the top layer.

**`captureVisibleTab` is 2 calls/sec** (`MAX_CAPTURE_VISIBLE_TAB_CALLS_PER_SECOND = 2`) and
returns physical pixels on HiDPI — which is exactly why Jarad's stated *relative*
coordinates is the payload that survives. `activeTab` is strictly more capable than
`<all_urls>` here, the reverse of how addendum §C reads.

**Four addendum §C facts are stale.** LNA shipped in Chrome 142 (2025-09-29), not 153;
HTTPS is a precondition for asking, not an exemption; Chrome 146+ splits the permission
into Local Network and Loopback and extends it to WebSockets/WebTransport/WebRTC; and the
WICG spec classifies `100.64.0.0/10` as *local* rather than ambiguous, with Chrome's own
Patrick Kettner stating extensions with correct host permissions "will not be impacted."
Net: §12 Q7 drops from discovery to confirmation. **[NOTE FOR ARCHITECTURE: correct
addendum §C before `bmad-create-architecture` and `bmad-create-epics-and-stories`
consume it.]**

**The keyboard budget is exactly four.** Suggested shortcuts cap at four, each must contain
Ctrl or Alt, Ctrl+Alt is banned outright, and global chords are limited to
Ctrl+Shift+[0..9]. The narrated journey has exactly four verbs — arm picker, open Cockpit,
file Ticket, discharge batch. Zero headroom.

**Dark mode has a seam the extension cannot see.** `prefers-color-scheme` in a side panel
reports the OS setting and never Chrome's own theme, and no API exposes the browser theme
(w3c/webextensions#242).

### Prior art (`research-annotation-prior-art.md`)

**Vercel Toolbar already ships Jarad's two payloads as one gesture in one armed mode** —
verbatim: "Click and drag while in commenting mode to automatically screenshot a portion
of the page and start a comment with it attached." Click yields an element-anchored comment
with no image; drag yields an image-bearing one. No mode switch between them.

**The confidence loop is solved by a tooltip, not by a reply.** The first field Chrome
DevTools' hover overlay prints is "The selectors of the element" — the overlay's whole job
is to prove which node it resolved *before* you commit. "User points → agent says okay →
user trusts it" does not need a round trip.

**DevTools disarms on click** ("Clicking in the webpage also turns off Inspect mode"), so
the pattern Jarad named by reference is single-shot and structurally does not support the
accumulate-then-discharge rhythm he described. Escape-to-cancel is undocumented in both
Chrome's and Edge's inspect docs — it is not an inherited convention.

**Element-anchored commenting with no mandatory image is shipped reality** in Vercel,
BugHerd and Pastel. **None of the three publishes its anchor serialization**, and the only
public spec — the W3C Web Annotation Data Model — answers drift with redundancy
("Multiple Selectors SHOULD select the same content… Consuming user agents MUST pick one")
while the W3C WG concedes "Robust Anchoring were under exploration, but no output were
produced." **No tool in the sweep documents what the user sees when an anchored element is
gone.**

**Two beats of the journey are unprecedented.** End-of-session batch submission exists
nowhere — Vercel, BugHerd, Figma and Pastel all commit per item on submit. And every tool
routes annotations to a *tracker*; none to an *agent*. The one-button finale is therefore
the least de-risked beat in the design.

**Linear answers the ADHD file-before-thinking cost** with a 3-minute grace window —
"Changes made to an issue's properties in the first 3 minutes are considered part of the
issue creation process, and won't be added to the activity log" — plus drafts that survive
Esc and persist across clients.

**Figma couples list and overlay as one state**: resolving "will hide the comment from both
the right sidebar and the canvas." Two views, never two states to reconcile.

**Excalidraw's real cost is not the drawing.** Its maintainer-confirmed 2MB/1440px limit
shrank a 1500×8500 page capture to roughly 100×550 — but the killing defect is that it has
**no output path at all**, so the finding must be retyped from working memory. That is
exactly where the session died.

**Standing tension:** every annotation-list surface in the category — Vercel's Inbox,
Figma's sidebar, BugHerd's kanban — is a place you *dwell*, and SM-C1 counts dwell as
failure. The running list Jarad asked for by name collides with the density prohibition.

## 2026-09-20 — Three decisions closed (Jarad)

Asked after both spines had drafted, so each requires a revision pass.

### 1. Dark mode — **a dark variant in the same register**

`prefers-color-scheme: dark` renders **Night Paper**: the paper is *dimmed, not inverted*.
DESIGN.md's authoring pass had already costed exactly this and shipped light-only with
Night Paper as an unshipped alternative — that is now promoted to the shipped answer.

Why dimming rather than inverting, per the document's own arithmetic: inversion is a second
design system, not a token swap. The One Black Rule means "stamped = inverted" has no inverse
left — the seven `#191713`-valued tokens (the stamp, the submit, the failure state, every
meaningful boundary, the focus ring) all measure 1.02:1 on an inverted panel. Night Paper
changes **nine values**, keeps ink at 12.72:1, keeps the stamp device intact, and holds the
signature at one value across both grounds.

Its one accepted failure, carried deliberately: the signature spine measures **2.56:1** on
Night Paper's `#E0D9C8`. The fix would be a deeper spine at 4.44:1, which breaks signature
invariance across modes — the document chose invariance and recorded the cost.

`[NOTE]` DESIGN.md argues the OS signal is an imperfect trigger, because in a side panel
`prefers-color-scheme` reports the **OS** setting and never Chrome's own theme
(w3c/webextensions#242). The decision stands on the OS signal; the caveat is recorded, not
designed around.

### 2. Freehand markup — **the image is not load-bearing**

"It has to feel like drawing" was the requirement, not "the PM needs a picture." Strokes render
as **SVG over the live DOM**. This deletes, outright:

- `captureVisibleTab` and everything it dragged in — the **2-calls-per-second** hard limit,
  physical-pixel HiDPI handling, viewport-only capture, and the whole capture-failure
  degradation path.
- The **`activeTab` permission**, and with it the gesture-scoped permission dance.

The payload changes shape. It was *image + relative coordinates*. It becomes **stroke geometry
in relative coordinates plus the elements the strokes cross** — their selectors and captured
context. That is strictly richer for an Agent that cannot see the page than a raster was: a
picture has to be interpreted, a selector set can be acted on.

Supersedes the decision log's earlier "requires an image" and EXPERIENCE.md Gaps item 5.

### 3. Element picker overlay — **hand-built closed shadow root**

Closed shadow root + CSS-layer reset + `position:fixed` + `z-index:2147483647`, the technique
DevTools' own UI uses. `chrome.debugger` / `Overlay.setInspectMode` is **rejected**: it pins a
"Sidepiece started debugging this browser" infobar to every tab on every activation,
suppressible only by a Chrome launch flag, and — the argument that actually decides it — the
native outline is *Chrome's* mark, not Sidepiece's. Direction 04's whole thesis is that a
Sidepiece mark must be unmistakably Sidepiece's on any page, and a browser-drawn outline cannot
wear `{colors.overlay.signature}`.

Accepted cost: some pages will break a fixed overlay via an ancestor `transform`/`filter`/
`contain` or the top layer. The design must say what the operator sees when that happens rather
than failing silently. No fallback to `debugger` is built.

Closes EXPERIENCE.md Gaps items 1 and 5, and DESIGN.md's dark-mode open question.

### Mock coverage walked

Every IA surface classified. **Mocked:** the identity header and its clone-path well, the
pane switch, the health marker, both `{components.turnCard}` variants, the composer with its
classification control and context chip, the ticket group header, the ticket row, the ticket
create box, the refetch control, the copy control, the state notice in both its shared and
per-pane shapes, the re-resolve control in primary / demoted / disabled form, the whole of
Night Paper, and `[v2]`'s hover outline, resolved-selector tooltip and comment bubble —
**fourteen of seventeen v1 components and three of eight `[v2]` ones.**

**Spine-only, and why each one stays that way:**

- **Extension icon states.** Chrome owns the frame, size, face and tracking; the four states
  plus one transient are titles on a 16px glyph. Nothing about them is a layout decision at
  284px, and v1 renders no badge at all.
- **`{components.commandString}`, and the two notices that mandate one** (DS-11, DS-14).
  The Cockpit may never invent command text, so rendering one would have meant fabricating a
  Bridge response. Derived instead: inside a notice the well is 248px → 35 mono characters a
  line before `word-break: break-all`. **This is the one v1 component whose fit at 284px this
  pass leaves untested**, and it is named as such rather than quietly skipped.
- **DS-1 and DS-21.** The only two states that render no `{components.stateNotice}` — one
  muted line, no failure glyph, re-resolve demoted or absent. A genuinely different shape from
  anything on the sheet, and PRD §12 Q4 makes DS-1 the browser's most common condition.
  **The strongest candidate for an eighth screen** if one is ever wanted.
- **`{components.degradedConnectionIndicator}`** (DS-15). Mixing an unrelated ambient state
  into a resolved or a failing screen would have made both dishonest.
- **`{components.jumpToLatest}`.** Its whole specification is that it is transient; a static
  sheet cannot show that.
- **The other twenty-six DS rows and every in-flight normal-path state.** Each renders into a
  shape already drawn — the shared notice (S4), the per-pane notice (S5), a Turn card (S1) or
  one muted line. Mocking them would be re-rendering S4 and S5 with different sentences,
  which is the *do not show fourteen screens* anti-pattern.
- **The rest of the `[v2]` annotation loop** — freehand layer, annotation row, discharge
  control, attachment chip and the Annotations pane. v2's own screen set; none of it
  constrains a v1 layout decision.
- **Focus, `::selection` and the `[v2]` achromatic fallback.** A static sheet showing one
  arbitrarily focused control reads as a selection state rather than as `:focus-visible`;
  `::selection` cannot appear in a screenshot; and the ΔE76 fallback needs a second page mock
  built specifically to trip it.

### Findings the mock produced, recorded rather than acted on

Drawing the spines surfaced thirteen findings. **None was resolved in this step**, because
every one is a design decision rather than an editorial defect and Finalize is not the place
to make new design decisions silently. They are recorded here so the next workflow inherits
them as *known*, not as discoveries. The four that will bite first:

1. **The composer cannot hold its own 188px cap.** At rest — chip collapsed, the standing
   Dispatched Command default, one line of draft — the specified stack computes to **233px**;
   with FR-10's URL revealed, **269px**. It fits 188px in exactly one state. Drawn
   overflowing rather than shrunk, per *Don't shrink type to fit*.
2. **The 188px cap and the one-scroll-region rule contradict each other.** `EXPERIENCE.md`'s
   IA table says the action bar "grows upward to a cap, then scrolls internally";
   `DESIGN.md`'s Rhythm says "One scroll region on screen: the body" and calls a nested scroll
   region in a 284px column a trap-the-wheel bug. Given finding 1 the composer reaches its cap
   in ordinary use, so **one of the two rules has to give.**
3. **The header's meta row has no measurement and is already nearly full.** Board chip +
   health marker + copy control is 183px of 284 on `SIDE` and 212px on `HOLOCENE`; add the
   degraded-connection indicator `DESIGN.md` also puts there and it overflows. Related: two
   Bridge readouts — the clip band's `BRIDGE UP · LAN` and FR-14's health marker — sit 40px
   apart and both state Bridge health.
4. **Five marks, N Board states, no mapping rule.** Nothing maps a Board's own state names
   onto the five `colors.state` values. An ordinary five-state Plane board already collapses
   two pairs, and `EXPERIENCE.md` anticipates Boards with eight states. The mapping drawn in
   S3 is the mock's, not the spines'.

The other nine: the classification control's 244px is derived from a geometry the Version
Seam table contradicts (a `[v2]` attachment slot beside it would make it 224px — the verdict
survives, the headline number does not); `paneSwitch` is specified two ways and `DESIGN.md`
contradicts itself between its prose and its own fits table, and its full-bleed seam cannot
share an edge with gutter-inset cells; the Dispatched card's band word and its outcome chip
collide on a terminal dispatch; the outcome chip puts variable content in a `{typography.micro}`
role its own 10.5 Floor Rule reserves for static chrome; the composer's only boundary is a
1.49:1 hairline if the grounds are taken literally, which fails `DESIGN.md`'s own audit test;
the disabled create box cannot carry "the reason" once the pane is scrolled; `DESIGN.md`'s
`CREATE IN 33GOD` and `EXPERIENCE.md`'s `Create on HOL` name different things, and the
11-character key the worst-case ticket measure is built on may be one the live Registry never
produces; and the cold-install drift above.

### Doc standards applied

`bmad-editorial-review-structure` then `bmad-editorial-review-prose`, in that order, against
both spines, deliberately conservative — these documents have been reviewed exhaustively and
their precision is the product. No measured figure, token value, DS code or quoted literal was
touched, and nothing was rewritten for taste.

**Structure: nothing substantive to change, and that is a real result.** Both documents were
checked against the Reference/Database model. Section order is canonical in both; every
invented section carries product-specific load; every heading's count matches its section's
contents; there is no true redundancy, only named cross-references to a single source of
truth. Verified mechanically rather than by eye: **25 `{components.*}` names on both sides
with no orphan in either direction, every `{colors.*}` / `{typography.*}` / `{spacing.*}` /
`{marks.*}` reference in `EXPERIENCE.md` resolving against `DESIGN.md`'s frontmatter, and
DS-1 through DS-28 complete with no gap.** One stale forward-pointer was cut: `DESIGN.md`'s
Shapes section still said `{rounded.pill}` was "flagged in **Gaps** for the spine's revision"
after that handoff had been applied, so it now records that the two documents agree.

**Prose: five fixes, all minimal.** A nested italic span in the handoff-list preamble that
terminated its own emphasis early and garbled the rest of the paragraph; "Five inks" opening
**The state set**, which the Glyph Law two paragraphs earlier contradicts by design —
`state.ok` and `state.unknown` share one value — now "Five states"; four occurrences of
*behaviour* against thirty of *behavior*; one clause that could not be parsed on a single read
("designing for behaviour nothing observed"); and four paragraphs left ragged by earlier
in-place amendments, rewrapped with their word sequences verified byte-identical. British
*colour* and *recognise* were left alone: they are consistent authorial voice in prose, and
the US spelling appears only inside token paths.

**Not applied:** the documents' own `[TAG — …]` annotation convention wraps blocks that
contain inner backticks in an outer code span, which renders imperfectly. It is the shared
convention of both spines, the architecture run consumed it without difficulty, and the prose
skill's own rule is to skip structural markup. Flagged, not rewritten — a mechanical sweep of
thirty-odd multi-line blocks is exactly the risk this pass was told not to take.

**Handoff.** Both spines are final. Common next: `bmad-create-epics-and-stories`, which reads
them as they stand. The thirteen mock findings above are the first thing it should look at,
because findings 1 and 2 are a contradiction between the two spines that a story will have to
resolve one way or the other.
